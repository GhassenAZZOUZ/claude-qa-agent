## Scope
- **In scope:** `POST /v1/exports` (returns `202` and an `id`), `GET /v1/exports/{id}`, `GET /v1/exports/{id}/file`, `DELETE /v1/exports/{id}`. Exports are processed asynchronously by a worker: `status` goes `pending → running → done | failed`. `status`, `reason` and `fileUrl` are server-owned and read-only: a client can't set them
- **Out of scope:** the worker's internals
- The shared API gateway, owned by the platform team, enforces authentication, rate limiting (429), body size (413) and content negotiation (406) for every service, this one included
- Implementation note from the spec: the worker currently names files `export-<id>.csv`; this may change
