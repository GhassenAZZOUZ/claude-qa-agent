# user-story-format

Agents that write user stories `Read` this file and follow it exactly. When
the format changes, change it here only.

## Story body

```markdown
## User Story

As a <actor>, I want <goal> so that <business value>.

**Constraints:**
- <constraint>
- ...

---

## Acceptance Criteria

| # | Title | Priority |
|---|-------|----------|
| AC-01 | <title> | `must` |
| ... | | |

<details>
<summary>View full Gherkin scenarios</summary>

**AC-01 — <title>** `must`
- **Given** <precondition>
- **When** <action>
- **Then** <observable, assertable outcome>

...

</details>

---

## Missing Information

- <open question that blocks writing tests>
- ...

---

## Definition of Done

- [ ] <measurable completion criterion>
- [ ] Test plan approved (`plan it`)
- [ ] Regression tests generated by `test-writer` and passing
- ...
```

Writers put their own header block **above** `## User Story`:
- `user-story-enhancer` (WAY 6) titles the section `## Enhanced User Story` instead of `## User Story`, and appends the original body in a `<details><summary>Original story (preserved)</summary>` block after the DoD
- `benchmark-gap-story-writer` (WAY 8) adds `# US-<n> — <title>` plus the **Gap source / Target today / Priority · Effort** lines

Every story body ends with the Output Watermark footer from `CLAUDE.md`.

## Acceptance criteria rules
- Gherkin Given / When / Then
- Cover: main happy path, every variant mentioned, error flows, edge cases, and non-functional requirements if stated
- At least one negative/failure path per story
- "Then" must be concrete, observable, and assertable. Never "the system should work correctly"
- Priority: `must` for core flows, `should` for important variants, `could` for nice-to-haves
- Number from AC-01 sequentially. `test-writer` traces tests back to these IDs (`**Covers:** AC-01`), so never renumber existing ACs on a re-run. Append new ones instead

## Test scenarios
Stories carry no Test Scenarios table: which tests to write, at which level and priority, is the test plan's job (`test-plan` skill, WAY 19), designed from these ACs with the categories of `requirements-analysis` §4. A story enhanced before WAY 19 may still have one: WAY 6 drops it on its next rewrite, and `plan it` reads its rows as hints.

## Missing Information
Questions that block writing tests (the `requirements-analysis` §2 readiness gate), one per line. An empty section means
"nothing blocking", so write `- none` rather than deleting the heading.
`e2e-session` and `write-tests` stop and ask the user while any question here
is unanswered.
